# Схема БД — черновик на утверждение (шаг 1)

Общие поля у **каждой** таблицы (дальше не повторяю):
`id UUID` · `branch_id → branches` · `created_at` · `updated_at` · `created_by → users`

Обозначения: `→` ссылка на таблицу, `?` поле может быть пустым.

## 1. Организация и настройки

| Таблица | Поля | Зачем |
|---|---|---|
| `branches` | название, город, код (`СТО1`) | Сеть до 10 СТО. Код идёт в номер наряда |
| `settings` | ключ, значение (JSON) | Всё, что Стас меняет без программиста (см. ниже) |
| `lifts` | номер, название, активен | 10 подъёмников |

**Что лежит в `settings`:**
- `branding` — название СТО, логотип (файл), иконка приложения (файл), акцентный цвет.
- `order_number_format` — шаблон номера, по умолчанию `{код}-{год}-{номер:6}` → `СТО1-2026-000123`; сброс счётчика: каждый год.
- `role_colors` — цвет интерфейса для каждой роли.

## 2. Сотрудники, права, присутствие

| Таблица | Поля | Зачем |
|---|---|---|
| `users` | ФИО, логин, пароль (хэш), PIN (хэш), роль → `roles`, телефон, активен | Вход по логину или PIN |
| `roles` | код, название, цвет интерфейса, системная (да/нет) | Менеджер, запчастист, кладовщик, контентщик, слесарь, админ + свои |
| `permissions` | код, название, группа | Справочник прав (заполняется программой). Пример: `orders.view_all`, `orders.view_own`, `money.accept`, `payroll.view_own`, `settings.access` |
| `role_permissions` | роль → `roles`, право → `permissions` | Набор прав роли |
| `user_permissions` | сотрудник → `users`, право, разрешить/запретить | Точечно добавить или забрать право конкретному человеку |
| `staff_cards` | сотрудник → `users`, номер карты (UID), подпись («брелок синий»), активна | Карта как от домофона. Потерял — блокируем, выдаём новую |
| `access_points` | название («Вход в цех», «Склад», «ПК приёмки»), тип (проходная / вход в CRM), считает присутствие (да/нет) | Где стоят считыватели |
| `attendance_events` | сотрудник, карта?, точка → `access_points`, направление (зашёл / вышел), время, способ (карта / вручную), комментарий | Каждое «пик» — запись. Табель и «кто где» считаются по ним |

**Права: как считаются.** Права роли + разрешения сотрудника − запреты сотрудника. У админа все права, и забрать их нельзя (иначе можно запереть самого себя).

## 2а. Зарплата — конструктор схем

Идея: у сотрудника есть **схема оплаты**, в ней несколько **строк**. Каждая строка — это «за что и сколько». Всё редактируется в «Настройки → Зарплата».

| Таблица | Поля | Зачем |
|---|---|---|
| `pay_schemes` | название («Запчастист стандарт»), действует с / по? | Шаблон схемы. Одну схему можно дать нескольким сотрудникам |
| `pay_scheme_lines` | схема, вид (оклад / процент / фикс за штуку), основа, фильтр, ставка, приоритет | Строка схемы (см. ниже) |
| `user_pay_schemes` | сотрудник, схема, действует с / по? | Кому какая схема. История сохраняется: старые наряды считаются по старой ставке |
| `part_groups` | название («ТО-расходники», «Профицит склада») | Группы запчастей для особых ставок |
| `part_group_items` | группа, номенклатура | Что входит в группу |
| `payroll_accruals` | сотрудник, наряд?, строка наряда?, строка схемы, основа (сумма), ставка, начислено, дата, статус (начислено / выплачено / отменено) | Начисления. Видно, из чего сложилась каждая гривна |
| `payroll_payouts` | сотрудник, период, сумма, кто выплатил | Выплаты |

**Строка схемы:**
- **вид:** `оклад` (сумма в день / в месяц) · `процент` · `фикс за штуку`;
- **основа:** сумма работ · цена продажи запчастей · наценка запчастей (продажа − закупка);
- **фильтр** (необязательно): группа запчастей · конкретная номенклатура · откуда деталь — «закупил под наряд» или «взял со склада»;
- **приоритет:** если подходит несколько строк, берётся самая точная (конкретная деталь → группа → откуда деталь → все остальные).

**Пример схемы «Запчастист»:**
| Вид | Основа | Фильтр | Ставка |
|---|---|---|---|
| оклад | — | — | 500 ₴ / день |
| процент | наценка | закупил под наряд | 10 % |
| процент | наценка | взял со склада | 5 % |
| фикс за штуку | — | группа «Профицит склада» | 50 ₴ |

**Когда начисляется.** Когда наряд **оплачен**. Слесарю — по своим выполненным работам, запчастисту — по запчастям, которые он подбирал. Отмена или возврат — начисление уходит в «отменено». Оклад начисляется за дни присутствия по табелю.

## 4. Наряд

| Таблица | Поля |
|---|---|
| `work_orders` | номер, клиент, авто, статус, сценарий (А/Б), менеджер, запчастист, слесарь, подъёмник, пробег на приёмке, жалоба клиента, тип оплаты (по факту / предоплата), сумма предоплаты, за что предоплата, ждёт предоплату (флаг), причина отмены?, закрыт админом с долгом (комментарий?) |
| `wo_status_history` | наряд, из статуса, в статус, кто, когда, комментарий |
| `wo_photos` | наряд, файл, этап (приёмка / диагностика / работа), находка?, автор |
| `wo_findings` | наряд, текст проблемы, согласовано (ждём / да / нет), кто согласовал, когда |
| `wo_works` | наряд, находка?, название, нормо-часы или фикс, кол-во, цена, исполнитель (слесарь), статус (ждёт / в работе / выполнена) |
| `wo_parts` | наряд, находка?, номенклатура → `parts_catalog`, кол-во, цена продажи, статус позиции, кто подобрал (запчастист) |

Статус позиции: `нужна → заказана → пришла → в резерве → выдана → установлена` (или `возврат`).

## 5. Склад и закупки

| Таблица | Поля |
|---|---|
| `parts_catalog` (номенклатура) | артикул, название, бренд, применимость (марки/модели, текст + теги), тип (новая / б/у) |
| `locations` | стеллаж, полка, место, подпись (`B / 2 / 3`) |
| `stock_items` | номенклатура, ячейка, себестоимость; для б/у: донор (марка, модель, год, VIN), состояние, цена, «на сайт» |
| `stock_photos` | позиция склада, файл |
| `stock_movements` | тип (приход / резерв / снятие резерва / выдача / возврат / списание / продажа / инвентаризация), позиция склада, кол-во (+/−), наряд?, строка наряда?, закупка?, кто, комментарий |
| `suppliers` | название, телефон, заметки |
| `purchases` | поставщик, статус (черновик / заказана / пришла частично / пришла), № накладной поставщика |
| `purchase_lines` | закупка, номенклатура, кол-во, цена, **под наряд?** (→ строка `wo_parts`) или на склад |
| `issue_requests` | наряд, кто запросил, статус (новый / выдан / отменён) |
| `issue_request_lines` | запрос, строка наряда `wo_parts`, кол-во, выдано |

**Остатки** — не поле, а сумма движений:
- на складе = приход + возврат − выдача − списание − продажа ± инвентаризация;
- в резерве = резерв − снятие резерва − выдача по резерву;
- свободно = на складе − в резерве.
